# Threat model and privacy assessment draft

Status: engineering draft for v0.2, not a completed DPIA/pentest or legal opinion.
Assets: phone channel access, encrypted provider credentials, private dossier references, identity signing/encryption keys; future declarations, scans, submitted snapshots and review/lottery evidence.
Trust boundaries: browser→BFF→API; workforce→Keycloak→signed JWT; API→Zalo delivery; API→DB/storage; future isolated workers and public evidence.

| STRIDE            | Threat                                                    | Implemented / outstanding controls                                                                                                                                                                                                                                          |
| ----------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Spoofing          | Forged role/JWT, weak login, guessed or replayed OTP      | Verify JWT signature/issuer/audience/client/expiry + signed AMR otp + org_admin; provider success + browser-bound single-use OTP + attempt/expiry limits. Mini App exchange stays disabled. Phone access does not prove legal identity.                                     |
| Tampering         | Cross-organization UUID, stale edits, owner reassignment  | Parameterized scoped queries, composite FKs, server-derived owner, If-Match conflicts, transaction writes. Development DB owner bypasses RLS; minimal runtime DB credentials/RLS for new routes remain outstanding.                                                         |
| Repudiation       | Silent staff changes, disputed authentication             | Append-only operational events and purpose/notice-version consent on successful phone authentication. Signed audit chains/checkpoints, full consent withdrawal/export and off-host replication remain outstanding.                                                          |
| Disclosure        | Credentials serialized to JS, public S3, phone in logs    | HttpOnly cookies, metadata-only provider responses, AES-GCM encrypted credentials/phone, keyed phone/OTP references, hashed sessions; private bucket; no sensitive documents/AI ingestion. Versioned key rotation, backup controls and retention worker remain outstanding. |
| Denial of service | OTP cost abuse, large payloads, DB exhaustion             | Phone cooldown/hourly quotas and peer quotas stored in DB, BFF bounded JSON, provider/network timeouts, DB pool bounds. Shared BFF peer limitation, edge quotas/trusted-proxy policy, paging/load tests remain outstanding.                                                 |
| Elevation/CSRF    | Customer becomes staff, global API-key proxy, cookie CSRF | Separate account/session systems, server-side staff JWT checks before each admin operation; no shared identity merge, no key-injecting proxy; exact-origin checks for BFF writes, SameSite cookies and OAuth state/PKCE. Project-manager assignments not enabled.           |

Privacy: do not enter real documents in this development release. Phone authentication sends a phone number and code to the investor's configured Zalo service only after the customer requests it; no production credentials or actual messages are used by tests. Record authentication consent as `phone-login-v1`; do not treat this as consent to advertising or all future dossier processing.

Before pilots define controller/processor duties, lawful purposes, notice ownership/version updates, retention/deletion, data export/correction, account recovery/phone reassignment, legal identity checks, impact assessment and incident/restore process. Dashboard currently holds preparatory references; stronger checks are needed before exposing sensitive documents. No protected-characteristic ranking or automatic eligibility decisions.

Residual risks: dev DB owner and S3/root credentials have broad rights; app-level filters are not a substitute for production DB privileges; revoking roles does not instantly invalidate previously issued JWTs; logout revokes the current local token/session, not all devices/IdP sessions. Provider templates/tokens expire or can be rejected. API/build/CI success does not certify production readiness. See [operating boundaries](ADMIN-AND-ZALO.md).
