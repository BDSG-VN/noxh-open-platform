# Private documents and deterministic filled forms

The dossier workspace accepts static PDF/JPEG/PNG up to 5 MiB. Names/metadata and binary bodies are encrypted (random AES-256-GCM object key; envelope key protected with the configured application key and owner/id AAD). Object keys are unguessable identifiers; there are no public/presigned download URLs. Downloads require the owner session or a staff application-review authorization checked before the internal service call. Storage credentials must be dedicated least-privilege credentials in production; the Compose root credential is development only.

Files start quarantined. ClamAV `INSTREAM` must return an exact clean response before download, extraction or evidentiary use. A missing/unreachable scanner, timeout or malformed response keeps the file quarantined. A rejected object cannot be promoted by the customer. Source bytes/hash/owner/key are immutable. Withdrawal removes the preparatory reference; retained submitted evidence cannot be withdrawn through this endpoint. Physical erasure requires the privacy/retention process and approved legal retention decision; this is not an automatic deletion promise.

For Compose, set `CLAMD_HOST=clamav` and start `docker compose --profile documents up --build --wait`. The optional image is ClamAV Debian 1.5.4; allocate memory/signature-update capacity and verify scanner health. The default remains without scanning and therefore refuses downstream processing. Native deployments set S3_ENDPOINT/S3_BUCKET/S3_REGION/S3_ACCESS_KEY/S3_SECRET_KEY and CLAMD_HOST/CLAMD_PORT. No clean-scanner override exists in product code. Tests use clearly isolated synthetic in-memory adapters.

OpenAI extraction is separate optional processing: organization and deployment opt-in, explicit file-specific consent (`document-extraction-v1`), current privacy notice acceptance and no restriction, the existing daily/customer/concurrency budgets, fixed server-side Responses endpoint, bounded structured output and no tools. Only the selected scanned file is sent, never every dossier file. Documents are untrusted data and never confer tool authority. `store:false` does not promise zero provider retention. No real provider credential/call was used for validation. Model capability and contractual/data-transfer review remain operator responsibilities. A user can instead type fields manually, so paid AI is not necessary for local form preparation.

Extraction fields carry page, short evidence excerpt, model, prompt version, source hash, confidence and immutable suggestions. Confidence is model-reported, not independently calibrated. Human-checked/corrected selections are encrypted separately; accepting suggestions never silently changes declarations or determines legal eligibility. Only accepted fields can be transferred from the UI into a draft form; fields may be completed manually.

Field mappings are project/release/source-hash/version/effective-date-bound. They contain explicit page, x/y, width/height, font size, key, label, requiredness and external-confirmation flags. A legal reviewer different from the author must approve. The source form release must itself be current and approved. Revoked/superseded/expired releases or mappings cannot create or confirm a new form. Existing artifacts remain downloadable with their provenance. Coordinate authoring uses PDF points from the lower-left origin; the JSON example in admin is structural only and is not a verified official mapping.

The PDF engine copies original source pages and overlays bounded text in the approved coordinates using an embedded Vietnamese font. It refuses overflow and invalid bounds. Unknown required values remain blank in a draft and block final confirmation. Drafts have a watermark; provenance is appended on a separate page to preserve original wording and margins. The customer downloads the draft, checks every field, explicitly acknowledges external attestations, then confirms a new print artifact. No government seal, signature, certification or eligibility decision is generated. Inputs, evidence hashes, template/mapping versions and final byte hashes are stored. The original draft object remains retained for traceability.

Before use with real data: independently inspect and approve actual project mappings, exercise malware/signature-update scenarios, perform storage/key backup and recovery, define deletion and legal holds, review provider transfers and run live provider/model tests with explicit operator authorization. All shipped native demonstrations are synthetic; no legal approval is fabricated.

The **Nộp hồ sơ** citizen workspace makes selected evidence, privacy-notice version, input version and the no-concurrent-household-application declaration explicit. A stable idempotency key is reused for retries of the same payload. The private receipt page separates platform receipt, manual review, supplements, decision and reconsideration. Demo receipts are visibly marked, and no platform receipt is represented as a government receipt. Customers can print or download their own receipt, see submitted files, supply scanned supplements, withdraw while permitted and exercise privacy rights. Actual legal intake remains controlled by deployment/legal gates; the complete statutory checklist still needs project review.

The investor's internal binary archive uses a distinct `identity_private.investor_files` registry and separate object encryption contexts. Only static PDF/JPEG/PNG up to 5 MiB are accepted, with project, active staff, record permissions and department checks. Files remain restricted, with immutable original bytes/hash/author, scan records and record-revision bindings. An unlinked file is readable only by its author with current records permission; other readers need an approved, visible linked record with the matching hash. Revoking a staff/project grant or the linked record blocks subsequent access. File upload alone does not publish a wiki/record revision. The normal retention/privacy process must decide erasure, holds and recovery; no automatic physical-deletion claim is made.
